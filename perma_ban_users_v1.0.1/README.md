# PermaBanUsers – REDCap External Module

The **PermaBanUsers** module prevents specific user accounts from being unsuspended through the REDCap User Rights interface. It is designed to ensure that certain suspended accounts—such as former staff, test users, or improperly created accounts—remain permanently inactive, regardless of who accesses the user management interface.

This module supports institutional access control by allowing administrators to enforce a "do not unsuspend" list that is easily maintainable through a standard REDCap project.

## Purpose

This module enforces the permanent suspension of specified REDCap user accounts. It is ideal for organizations that require an extra layer of control over account reactivation, particularly in cases where accounts should never be re-enabled.

## Who Should Use This Module

- **Super Admins**: Responsible for configuring the module and linking it to the ban list project.
- **Data Management (DM) Team**: Responsible for maintaining the list of banned users in a designated REDCap project.

## Key Features

- Hides banned usernames from the “Unsuspend User” dropdown in the User Rights page.
- Prevents manual POST-based attempts to unsuspend banned accounts.
- Matches usernames in a case-insensitive manner.
- Requires the ban record to be **marked as complete** to take effect.
- Ban list is stored and managed in a REDCap project, editable by authorized staff.
- Automatically applies enforcement globally across all projects.

## Setup Instructions

### Step 1: Prepare the Ban List Project

Create a REDCap project with a form that includes at minimum:

- `username` (Text, **Required**): the REDCap account username to be permanently banned.
- `[your_form_name]_complete` field (automatically generated by REDCap, **Required**): this must be set to “Complete” for the ban to take effect.

> **Important:** The module assumes the entire list of banned users is stored in a **single form**. Only the **first instrument** detected in the project will be used. If there are multiple forms, only the first one (by order in the data dictionary) will be checked, and the others will be ignored.

Optionally, add fields such as:

- `reason` – description of why the user is banned
- `ticket_reference` – link to a support or HR ticket
- `banned_by` – staff member who entered the record
- `date_banned` – manually entered or defaulted to [today]

> **Note:** Only users whose records are marked as “Complete” will be treated as permanently banned.

### DM Team Permissions: What You Can and Cannot Change
| Component | Can DM Edit? | Notes |
|----------|--------------|-------|
| `username` field | ❌ **Do not rename or delete** | This field name is hardcoded in the module and required for functionality. Only the value can be edited. |
| `[form_name]_complete` field | ✅ Mark as complete/incomplete | Used to activate or deactivate the ban. Setting to "Incomplete" unbans the user. |
| Other form fields (e.g., `reason`, `ticket_reference`) | ✅ Safe to add, edit, or delete | These are ignored by the module and exist for documentation purposes. |
| Record status | ✅ Can delete or un-complete | Deleting a record or marking it incomplete removes the user from the ban list. |
| Adding additional forms | ⚠️ Not recommended | The module only checks the first form. Adding multiple instruments may cause unexpected behavior. |

### Step 2: Configure the Module

1. Go to **Control Center → External Modules → System Settings**.
2. Enable the **PermaBanUsers** module.
3. Enter the Project ID (`perma_ban_project_id`) of your ban list project.
4. Save the configuration.

Once enabled, the module will automatically apply its restrictions on all projects.

## Using the Module

### To Permanently Ban a User:

1. Ensure the user account is already suspended via the Control Center.
2. Open the ban list project.
3. Create a new record.
4. Enter the REDCap username in the `username` field (case-insensitive).
5. Mark the record as **Complete**.
6. Optionally fill out reason, reference, and other fields.
7. Save the record.

The module will automatically hide this username from the unsuspend list and block any attempts to reactivate it.

### To Unban a User:

To remove a user from the ban list, you may:
- **Delete the record** from the project, or
- **Change the record status to incomplete** (i.e., set `[form_name]_complete` to anything other than `2`)

In either case, the user will no longer be considered "perma-banned" the next time the module checks.

> **Reminder:** The ban check is dynamically performed using the REDCap API. If the record is missing or incomplete, the username is no longer treated as banned.

## Notes and Recommendations

- **Accounts must be suspended first**. The module does not perform suspension—it only prevents reactivation.
- **Records must be marked as complete** in the form for bans to take effect.
- **Case-insensitive matching** ensures that `TestJordan`, `testjordan`, and `TESTJORDAN` are treated as the same.
- **Typos or unrecognized usernames** in the ban list will be silently ignored. Ensure data accuracy.
- **No impact on login**: suspended users cannot log in or reset their password; this module ensures they remain in that state.

## Integration Notes

This module relies on an existing `redcap_user_rights` hook implementation already in use at this institution. The existing hook is responsible for:

- Displaying user role recommendations and instructional banners
- Rendering the "unsuspend user" dropdown manually
- Injecting other JavaScript-based enhancements

**The PermaBanUsers logic has been injected into this pre-existing hook**, and specifically depends on:

- Access to the `$banned` array generated by the External Module
- The unsuspend dropdown being rendered using a custom `<select>` tag in PHP
- A JavaScript block that filters the `<select>` list after the page loads

### Warning:

If future developers modify the `redcap_user_rights` hook—for example, by changing how the dropdown is rendered, removing the manual select logic, or replacing the UI rendering with native REDCap features—**the ban enforcement logic may silently stop working.**

To ensure continued functionality:

- Do not remove or refactor the manual rendering of the unsuspend user `<select>` dropdown.
- Ensure that the JavaScript block which removes banned usernames remains intact.
- Clearly communicate this dependency in your technical documentation and change logs.


Required code addition to current suspension hook implementation:
```
function redcap_user_rights($project_id)
{
	// Before running unsuspend SQL
	if (\ExternalModules\ExternalModules::isModuleEnabled('perma_ban_users')) {
        $module = \ExternalModules\ExternalModules::getModuleInstance('perma_ban_users');
        $banned = $module->getPermaBannedUsers();
    }
    ...

    // Add a script to remove the banned users from the select options
		if (\ExternalModules\ExternalModules::isModuleEnabled('perma_ban_users')) {
            echo "<script>
            document.addEventListener('DOMContentLoaded', function() {
                const bannedUsers = " . json_encode($banned) . ";
                const select = document.querySelector('select[name=\"unsuspenduser\"]');
                if (select) {
                    [...select.options].forEach(option => {
                        if (bannedUsers.includes(option.value.toLowerCase())) {
                            option.remove();
                        }
                    });
                }
            });
            </script>";
        }

    ...
} 
```
